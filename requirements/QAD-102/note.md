# Simulated requirement questions and observations

- [ ] Q1 — The helper text on the Passed card mentions flaky, but the card value shows only passed; the pass-rate numerator adds flaky separately. Whether to change the helper text is undecided; the two counts must not be merged.
- [ ] Q2 — AC-03 says the summary card has a "pass-rate change" and uses the previous date with data in the scope as the baseline, but it does not say how the change is calculated or displayed (for example, a percentage-point difference or a relative change, and whether it has a sign and unit). So the change value cannot be asserted when a previous date with data exists, and "the baseline is the previous date with data, not necessarily the previous calendar day" cannot be verified from a visible result. This blocks those two assertions; this design writes no scenario for them.
- [ ] Q3 — The requirement does not state the display precision of the pass rate (for example 80% or 80.0%); AC-01 does not say where the four counts are shown; AC-04 does not say where "—" is shown. This design uses data that gives whole-number results, and assumes the four counts and the pass rate are all shown in the summary. Whether the trend, project groups, and Recent runs also show "—" when executed is zero is not stated, so no scenario is written for it. This does not block the current scenarios.
- [ ] Q4 — QAD-101 AC-02 and AC-03 of this Story both say the summary uses the filter scope. QAD-101's scenarios already assert the summary under filters, so this Story only covers "the latest date with data" under the default filters. Also, the requirement does not say whether the summary merges all runs of that day when the latest day with data has several runs. So no summary scenario with several runs on that day is written. This does not block the current scenarios.
