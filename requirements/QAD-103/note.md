# Simulated requirement questions and observations

- [ ] Q1 — The current threshold first counts history records including skipped, then removes skipped to calculate the score. So passed/failed/skipped can enter the ranking and show runs=2; whether to require at least three non-skipped records is undecided.
- [ ] Q2 — The UI title Consistently failing tests and the README say "always failing", but top_failures actually collects tests that failed at least once, so intermittent failures can appear as well. Do not assert that the two lists are mutually exclusive; whether to tighten the failure list rule is undecided.
- [ ] Q3 — The requirement does not say which fields each flaky ranking row shows (whether the score is shown, and in what format), or how many entries the "recent history" shows. This design only asserts whether a test enters the ranking, the order within the ranking, and the order of the recent history; the recent history uses only 3 records. This does not block the current scenarios.
- [ ] Q4 — AC-06 says "not having enough history does not mean the test is stable", but the requirement does not define how "stable" is shown, nor how a test with too little history appears on the page. So no observable assertion can be written; scenario 03 only asserts that a test with too little history does not enter the ranking. This does not block the current scenarios. Source: QAD-103 AC-06; raised by the independent review.
